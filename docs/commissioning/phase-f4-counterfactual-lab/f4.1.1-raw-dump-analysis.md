# f4.1.1 raw-provider dump analysis

## Retained failed runs

The preserved failed commissioning manifests are:

- `2382988a-c1aa-4346-8e02-2569c44b4a50`
- `6d514557-82a2-4e76-8894-87267ee2f3cb`

Both contain the same scenario hash
`1e17d73771b1c828a190555c2946b9dc8ee1a73267e32333d111f73699be4efa`,
the same balance mutation and assertion, genuine `anvil Version: 1.8.1`, and
different nested full-state fingerprints before and after revert.  Both
quarantined and their manifests remain untouched.

The old implementation intentionally persisted only hashes, not the exact raw
dump or its decoded structure.  Therefore the original compressed bytes
cannot be reconstructed from those manifests.  That evidence-provenance gap
is part of the defect: a raw serialization mismatch was treated as the sole
restoration oracle while the serialization needed to diagnose it was not
retained.

Exactly one decoded path changed:

| `/block/timestamp` | `0x1` | `0x6a948f66` | `PROVIDER_SERIALIZATION` | `ANVIL_V1_8_1_GENESIS_BLOCK_ENV_REANCHOR_V1` | no |

No `/accounts`, `/blocks`, `/transactions`, or `/historical_states` path
changed.  The canonical latest header—including timestamp, hash, parent hash,
state root, beneficiary, gas and blob fields—was identical before and after.

## Classification basis

Pinned Foundry source defines the dumped `block` as the in-memory `BlockEnv`.
The `evm_revert` implementation restores database and canonical storage, then
resets the time manager and reconstructs `BlockEnv` from the canonical
snapshot block header.  On a default genesis process, the initial serialized
`BlockEnv.timestamp` is the sentinel `1`, while the canonical genesis header
has the launch timestamp.  Revert replaces the sentinel with that unchanged
canonical timestamp.

The rule is accepted only for this one pointer and only when all of the
following are simultaneously true: pinned release and commit, block zero,
before value `0x1`, after value equal to the unchanged canonical head
timestamp, equal canonical heads, and equal semantic fingerprints.  A change
to any other block field—or this path under any other conditions—remains
canonical-chain drift and quarantines.  Unknown paths remain `UNKNOWN` and
quarantine.

This is separating provider serialization identity from verified
execution-state identity.  It is not ignoring metadata.
